# AI File Quality Score Foundation

Roadmap task: `RMAP-FILE-QUALITY-SCORE-M1-FOUNDATION`

This foundation adds a local-only `file-quality-score-v1` contract for deterministic request and file readiness scoring. It is review support for admins and future customer-safe surfaces; it is not approval for tuning, checksum work, flashing or delivery.

## What It Scores

- Safe request metadata completeness: vehicle, engine, ECU/TCU, read method and hardware/software context.
- Structured File Expert evidence: analyzer result presence, file inspection summary and ORI/MOD comparison summary.
- Integrity and compatibility signals: size compatibility, structured integrity issues and File Expert risk level.
- Analyzer explainability: conclusion, stock/modified classification, ECU identification, pattern/change summaries and confidence.
- Service context: requested service/options and whether customer notes exist, without exposing note text.
- Review gate state: explicit blockers, quality status and final human expert decision.

No raw binary or hex data is read, stored or projected. The module never reads raw binary bytes, hex previews, offsets, storage paths, signed URLs, hashes, filenames, customer identifiers, sample IDs or admin notes. It consumes only already-structured summaries and boolean/count-style context.

## States

- `provider_unavailable`: an unavailable provider response before fallback. No score should be treated as generated.
- `provider_unavailable_fallback`: deterministic non-AI fallback score generated after unavailable provider state.
- `provider_error_fallback`: deterministic non-AI fallback score generated after a configured provider fails locally.
- `deterministic_fallback`: deterministic non-AI score generated by local rules.
- `invalid_input`: insufficient structured evidence; score is `0`, grade is `not_scorable`.

Fallback output always has `isAiGenerated: false`.

## Projection Boundary

Customer projection may show:

- score, grade, readiness and confidence;
- customer-safe factor labels and generic evidence reasons;
- missing information;
- risk flags and recommendations;
- human-review requirement and blocked customer actions.

Customer projection must not expose:

- provider ID, kind, status, model name or prompt version;
- fallback internals;
- factor weights;
- raw binary, hex, offsets, hashes, filenames, storage paths, signed URLs;
- customer identifiers, sample IDs or admin-only notes.

Expert projection may show provider/fallback status, factor weights, normalized evidence counts, required human checks and blocked production actions. Expert projection is still review support only.

## Blocked Production Actions

The foundation blocks these actions until separate owner-approved rollout work exists:

- live provider rollout;
- customer-ready MOD export;
- checksum approval;
- flash-safety approval;
- automatic delivery;
- production quality persistence.
